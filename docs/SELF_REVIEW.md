# Senior ML engineering self-review

This review separates fixes implemented in this version from remaining work. “Fixed” means the stated narrow failure is addressed, not that the entire risk category is solved.

| # | Problem | Why it matters | Change made / next improvement | Status |
|---|---|---|---|---|
| 1 | Model could be unavailable | A fake semantic score would mislead users | Explicit MiniLM download dependency; errors return 503; LSA requires an explicit environment choice and visible warning | Fixed |
| 2 | Long resumes can be truncated | Relevant evidence at the end is lost | Overlapping chunks pooled and renormalized; tail-coverage test. Replace word approximation with tokenizer windows next | Mitigated |
| 3 | Skill hallucination | Users could receive credit for nonexistent skills | Template explanations quote explicit matched text; model similarities never create profile skills | Fixed for generated explanations |
| 4 | Alias inconsistency | sklearn and scikit-learn could mismatch | Separate versioned taxonomy and boundary-aware patterns; alias tests | Fixed for listed aliases |
| 5 | Negated/future skills counted as mastery | “No AWS” or “learning Docker” could raise score | Conservative local negation/learning filters with tests. Complex scopes still need linguistic parsing | Mitigated |
| 6 | Required/preferred requirements conflated | Nice-to-have gaps could dominate ranking | Heading/inline clause extraction, required wins on duplicates, required skills scored separately | Mitigated; alternatives remain ambiguous |
| 7 | Overlapping employment double-counted | Inflated experience biases compatibility | Merge month-level intervals; ambiguous year-only durations remain unknown | Fixed for supported date patterns |
| 8 | Missing information silently becomes zero/perfect | Scores become hard to interpret | Null factors, explicit coverage, renormalized weights and contribution breakdown | Fixed mechanically; ranking trade-off remains |
| 9 | Unjustified weights and correlated factors | Index lacks empirical meaning | Equal priors explicitly uncalibrated; documented held-out calibration and ablation plan. No human data to learn defensible weights | Open scientific limitation |
| 10 | Unsafe/malformed uploads | Parser crashes, archive bombs, resource exhaustion | Signatures, extension limits, DOCX expansion/macro/path checks, bounded subprocess, 12-second deadline, 5 MB file / bounded ASGI body including chunked requests | Mitigated; not antivirus |
| 11 | Cross-session access | Private resumes could be exposed | Hashed high-entropy tokens, server-side ownership checks, isolation tests, no anonymous reads of private records | Fixed for implemented API paths |
| 12 | Indefinite source-file retention | Unnecessary privacy exposure | Original file bytes are not persisted; cascade deletion removes session data/results; no cross-request embedding text cache | Mitigated; structured evidence remains until deletion |
| 13 | PII and university bias in embeddings | Protected attributes and prestige could influence ranking | Exclude candidate-name line, contacts, university strings and common sensitive metadata; name invariance test | Mitigated; residual proxies and unstructured names remain |
| 14 | Repeated model inference during ranking | CPU latency scales poorly | Per-request embedding cache reuses profile/project/job vectors; singleton model initialization and encoder lock | Improved; no persistent vector index or ANN |
| 15 | Concurrent repeated writes can violate uniqueness | Multiple UI requests could fail | PostgreSQL/SQLite ON CONFLICT upserts for match/recommendation pairs; repeated-write tests | Fixed for pair uniqueness |
| 16 | Fabricated “market statistics” | Sample data could be mistaken for real demand | Authored source metadata, visible sample counts, no live vacancy claims, percentages computed server-side | Fixed for data labeling |
| 17 | Weak evaluation and training leakage | Good fixture results do not establish real-world quality | Human labels explicitly null; smoke-only reports; independent annotation and grouped holdout protocol | Open scientific limitation |
| 18 | Learning priority ignores actual usefulness | Popular skills may not improve target coverage | Exact counterfactual required-skill coverage gain with role-specific denominator; demand and foundation tie-breaks | Improved; no learning-resource quality or mastery model |
| 19 | Co-occurrence confused with causation | Users may infer prerequisites or salary effects | Symmetric count matrix, counts and caveats; no causal salary claims; fictional salary metadata | Fixed for presentation |
| 20 | Non-standard resume sections, scans, multilingual text | Missed extraction can distort scores | Table-aware DOCX order, conservative unknowns, explicit OCR notice, selectable profile evidence | Open; add OCR/layout models and language evaluation |
| 21 | Production operations incomplete | Local reliability does not establish deployment readiness | Docker, PostgreSQL schema, non-root backend, reverse-proxy body limits, local-only exposed port, test suite; Docker/PostgreSQL runtime not available for verification here | Open deployment gate |
| 22 | Schema evolution lacks migrations | create_all cannot safely upgrade databases | Initial PostgreSQL DDL included; add/review Alembic migrations before production schema changes | Open |
| 23 | Browser token persistence and account recovery | XSS could expose token; cleared storage loses access | No external scripts except optional font CSS; CSP at Nginx; React text escaping; clear delete flow. Replace with OIDC and HttpOnly cookies for public deployment | Open for public multiuser use |
| 24 | In-process rate limiting / unbounded anonymous accounts | Not effective against distributed abuse | Local per-IP bound, session quotas, body caps, concurrency limit. Nginx traffic shares a proxy IP; use trusted proxy + Redis limits and authenticated accounts before public exposure | Open for internet scale |
| 25 | Education and tenure requirements can amplify structural disadvantage | Absence of explicit protected features is insufficient | University rank omitted; equivalence/optional degrees excluded; no gap penalty. Audit role-specific degree/tenure necessity and subgroup impact with real data | Open fairness limitation |
| 26 | Large Plotly payload | Slower first chart load on weak devices | Lazy-load charts in a separate chunk and show readable fallback. Use a custom Plotly bundle or narrower chart library if requirements permit | Mitigated |
| 27 | Unit/API/build checks do not establish usable UI | Visual overflow or browser behavior may remain | Responsive layouts, semantic labels, keyboard focus, reduced motion, chart tables; browser visual QA was not run | Open verification limitation |

Most consequential implemented fixes are evidence-only skill credit, required/preferred separation, unknown-factor handling, bounded uploads, access isolation, deletion cascades, per-request embedding reuse, explicit sample labeling and repeat-write upserts. The lack of human validation, deployment runtime verification and broad fairness evidence is not concealed by those fixes.
